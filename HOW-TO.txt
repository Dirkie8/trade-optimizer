# How walk through works:
#%%%---------------------
########Without wt:
For each of 50 random parameter combinations:
    Run backtest on 80% of data (training)
    → ONE backtest per parameter set
    
Total: 50 backtests

Then take top 50 and evaluate on 20% (test set)
Total: 50 + 50 = 100 backtests

######## With wt:
For each of 50 random parameter combinations:
    Split data into 5 folds
    
    Fold 1: Train on [0-20%] → Test on [20-40%]  ← 1 backtest
    Fold 2: Train on [0-40%] → Test on [40-60%]  ← 1 backtest
    Fold 3: Train on [0-60%] → Test on [60-80%]  ← 1 backtest
    Fold 4: Train on [0-80%] → Test on [80-100%] ← 1 backtest
    
    Average results from 4 test folds
    → FOUR backtests per parameter set (actually 4, not 5, because fold 1 has no training data)

Total: 50 × 4 = 200 backtests during optimization

Then still evaluate top 50 on hold-out test set
Total: 200 + 50 = 250 backtests

Execution realism and risk controls (optional)
----------------------------------------------
You can enable a few optional controls in `configs/main_config.yaml` under the `account` block
to make backtests more realistic and to prevent the account from “drying up”. All are optional
and default to off if omitted.

Keys:
- max_drawdown_stop_pct: Stop trading once peak-to-trough drawdown exceeds this percent.
- min_stop_pips: Skip trades whose stop-loss distance is tighter than this (in pips).
- slippage_pips: Apply additional unfavorable slippage at entry and exit (in pips) on top of spread.
- min_size: Skip trades whose calculated size is below this threshold (prevents micro-trades).
- leverage: Cap position size by margin: notional <= equity * leverage.

Example account block with conservative settings:

  account:
    starting_balance: 100
    risk_per_trade: 0.01
    spread_pips: 0.2
    commission_per_trade: 0.0
    leverage: 100
    max_drawdown_stop_pct: 30     # stop trading after 30% drawdown
    min_stop_pips: 3              # ignore SLs tighter than 3 pips
    slippage_pips: 0.1            # add 0.1 pips slippage per fill
    min_size: 0.0001              # ignore trades smaller than this size

Notes:
- Spread is modeled as half at entry and half at exit (unfavorable), in addition to slippage if set.
- These settings are optional. If omitted or set to 0, default behavior is unchanged.
- The walk-forward optimizer’s validation split is controlled by its CLI flag `--validation_ratio` (batch runner passes it through).
